Velum Via — Política de Privacidad

Última actualización: 31 de julio de 2026

Esta Política de Privacidad explica cómo Velum Via trata la información relacionada con el uso de la aplicación, incluidos los mensajes protegidos, los datos almacenados localmente, los enlaces compartidos, la infraestructura remota, la autenticación biométrica, la cámara, las suscripciones y las opciones de eliminación.

Velum Via está diseñada bajo principios de minimización de datos y privacidad por diseño. La aplicación busca tratar únicamente la información necesaria para crear, compartir, proteger, visualizar, revocar y eliminar mensajes, así como para administrar las funciones contratadas por el usuario.

1. Responsable y contacto

Velum Via es desarrollada y operada bajo la marca Velum.

Para consultas sobre privacidad, protección de datos, eliminación de información o funcionamiento de la aplicación:

  • Privacidad: privacy@usevelum.com
  • Soporte: support@usevelum.com
  • Sitio web: https://usevelum.com/
  • Política de Privacidad: https://usevelum.com/privacy/

2. Alcance

Esta política se aplica a la aplicación móvil Velum Via y a las páginas oficiales vinculadas desde su ficha de Google Play.

La política describe la versión de la aplicación que puede incluir:

  • creación y lectura de mensajes protegidos;
  • almacenamiento local de mensajes y preferencias;
  • generación y apertura de enlaces de mensajes;
  • almacenamiento remoto de contenido cifrado y metadatos mínimos;
  • lectura única, límites de lectura, expiración y revocación;
  • frase o clave de lectura;
  • autenticación biométrica o credencial del dispositivo;
  • detección local de presencia mediante la cámara;
  • historial privado;
  • funciones gratuitas y funciones Premium;
  • compras o suscripciones administradas mediante Google Play.

Velum Via no requiere crear una cuenta propia, proporcionar un nombre, un correo electrónico ni un número de teléfono para utilizar sus funciones principales.

3. Resumen del tratamiento de datos

3.1 Datos almacenados localmente

Velum Via puede almacenar en el dispositivo:

  • mensajes creados, recibidos, enviados o archivados;
  • contenido cifrado y datos necesarios para abrirlo;
  • claves, secretos o materiales criptográficos almacenados mediante mecanismos seguros del dispositivo;
  • estado de lectura, disponibilidad, revocación y expiración;
  • preferencias de privacidad y seguridad;
  • configuración del historial privado;
  • configuración de protección biométrica;
  • nivel de acceso Free o Premium y datos locales de uso de funciones limitadas;
  • información técnica necesaria para el funcionamiento de la aplicación.

Estos datos permanecen bajo el control del usuario y se utilizan para brindar las funciones de la aplicación.

3.2 Mensajes protegidos y almacenamiento remoto

Cuando el usuario crea o comparte un mensaje remoto, Velum Via puede transmitir a su infraestructura:

  • el contenido del mensaje cifrado antes de salir del dispositivo;
  • un identificador aleatorio del mensaje;
  • tokens o identificadores aleatorios necesarios para permitir el acceso, la lectura o la revocación;
  • reglas de lectura única o cantidad máxima de lecturas;
  • fecha y hora de creación;
  • fecha y hora de expiración, cuando corresponda;
  • estado de lectura, revocación, disponibilidad o eliminación;
  • versión o formato técnico del mensaje;
  • metadatos mínimos necesarios para ejecutar las reglas de seguridad.

Velum Via no necesita almacenar el texto plano del mensaje en el servicio remoto para prestar esta función. El servidor conserva principalmente el contenido cifrado y los metadatos operativos necesarios.

El enlace compartido puede contener o permitir obtener información necesaria para abrir el mensaje. Por este motivo, el usuario debe tratar el enlace como información confidencial y compartirlo únicamente con la persona destinataria.

3.3 Datos técnicos de conexión

Al comunicarse con la infraestructura remota, los proveedores técnicos pueden procesar automáticamente datos habituales de conexión, como:

  • dirección IP;
  • fecha y hora de la solicitud;
  • tipo de dispositivo;
  • versión del sistema operativo;
  • versión de la aplicación;
  • identificadores técnicos de la solicitud;
  • registros de errores, disponibilidad y seguridad;
  • información necesaria para prevenir abuso, fraude o accesos no autorizados.

Estos datos no se utilizan para leer el contenido en texto plano de los mensajes ni para crear perfiles publicitarios.

3.4 Datos biométricos

Velum Via puede utilizar los mecanismos de autenticación disponibles en Android, como huella digital, reconocimiento facial o credencial de bloqueo del dispositivo.

La autenticación es administrada por el sistema operativo. Velum Via:

  • no recibe la plantilla biométrica;
  • no copia la huella ni el rostro;
  • no almacena datos biométricos;
  • no transmite datos biométricos a sus servidores.

La aplicación solo recibe del sistema operativo el resultado de la autenticación, por ejemplo, si fue aprobada, cancelada o rechazada.

3.5 Cámara y detección de presencia

Velum Via puede solicitar acceso a la cámara para comprobar localmente si existe presencia frente al dispositivo durante la lectura de un mensaje protegido.

La cámara se utiliza para aplicar medidas visuales de privacidad, como ocultar o bloquear el contenido cuando no se cumplen las condiciones de lectura configuradas.

Para esta función:

  • el procesamiento está diseñado para realizarse localmente;
  • Velum Via no está diseñada para guardar fotografías o videos;
  • las imágenes de la cámara no se incorporan al mensaje;
  • las imágenes o el video no se envían al backend de Velum Via;
  • no se crea una base de datos de rostros ni se realiza identificación remota de personas.

La detección de presencia no equivale a una garantía de identidad de la persona destinataria.

3.6 Compras y suscripciones

Las compras y suscripciones se procesan mediante Google Play Billing.

Google Play puede tratar la información necesaria para gestionar el pago, la facturación, la suscripción, los reembolsos y la prevención del fraude de acuerdo con sus propias políticas.

Velum Via puede recibir de Google Play información limitada, como:

  • producto o plan adquirido;
  • estado de la compra o suscripción;
  • fecha y vigencia del acceso;
  • token o identificador técnico de compra;
  • estado de confirmación, cancelación, renovación o restauración.

Velum Via no recibe ni almacena el número completo de la tarjeta, los datos bancarios completos ni las credenciales de pago del usuario.

3.7 Consultas de soporte

Si el usuario escribe voluntariamente a soporte o privacidad, Velum puede tratar:

  • dirección de correo electrónico;
  • nombre, si el usuario decide proporcionarlo;
  • contenido de la consulta;
  • archivos o capturas que el usuario adjunte;
  • datos técnicos necesarios para resolver el problema.

No deben enviarse mensajes privados, claves de lectura, enlaces activos, secretos, contraseñas ni información sensible que no sea indispensable para la consulta.

4. Datos que la aplicación no solicita como requisito general

Velum Via no requiere, como condición general para utilizar sus funciones principales:

  • nombre real;
  • cuenta de usuario propia;
  • dirección postal;
  • número de teléfono;
  • lista de contactos;
  • ubicación precisa;
  • historial de llamadas;
  • mensajes SMS;
  • fotografías o videos personales;
  • documentos de identidad;
  • datos biométricos almacenados por Velum Via.

La aplicación tampoco vende datos personales ni utiliza el contenido de los mensajes para publicidad personalizada.

Si una versión futura incorpora una función que necesite otra categoría de datos, esta política y la declaración de Seguridad de los datos de Google Play serán actualizadas antes o junto con su publicación.

5. Finalidades del tratamiento

Velum Via puede tratar información para:

  • crear, cifrar, compartir y abrir mensajes protegidos;
  • aplicar lectura única, cantidad máxima de lecturas, expiración y revocación;
  • mantener las bandejas de Recibidos, Enviados e Historial privado;
  • proteger secciones mediante biometría o credencial del dispositivo;
  • aplicar detección local de presencia;
  • administrar el acceso a funciones Free y Premium;
  • verificar, restaurar y mantener compras o suscripciones;
  • operar y proteger la infraestructura remota;
  • prevenir abuso, fraude, automatización maliciosa o acceso no autorizado;
  • diagnosticar fallos y mantener la compatibilidad y estabilidad;
  • responder consultas de soporte o privacidad;
  • cumplir obligaciones legales válidas.

6. Proveedores y destinatarios

Velum Via no vende información personal.

La información puede ser procesada de forma limitada por proveedores que ayudan a operar la aplicación:

6.1 Supabase

Velum Via utiliza infraestructura basada en Supabase para almacenar y gestionar mensajes remotos cifrados, tokens, reglas de lectura, expiración, revocación y otros metadatos operativos mínimos.

Supabase puede procesar datos técnicos de infraestructura y conexión para prestar, proteger y mantener sus servicios.

6.2 Google Play y Android

Google Play distribuye la aplicación y administra las compras y suscripciones. Android administra permisos, autenticación biométrica, credenciales del dispositivo y otras funciones del sistema.

Estos servicios tratan información conforme a sus propias políticas.

6.3 Proveedor de correo electrónico

El proveedor de correo utilizado por Velum puede procesar la dirección y el contenido de los mensajes enviados voluntariamente a soporte o privacidad.

6.4 Autoridades y obligaciones legales

Velum puede conservar o divulgar información cuando exista una obligación legal válida, una orden competente o cuando resulte razonablemente necesario para proteger la seguridad de usuarios, terceros, la aplicación o sus servicios.

Cuando sea legalmente posible, se procurará limitar la información comunicada a lo estrictamente necesario.

7. Transferencias internacionales

Los proveedores tecnológicos utilizados por Velum Via pueden operar infraestructura o procesar datos en países distintos de aquel donde se encuentra el usuario.

Cuando exista una transferencia internacional, se aplicarán las medidas contractuales, organizativas y técnicas disponibles a través de los proveedores correspondientes. El contenido remoto de los mensajes se mantiene cifrado conforme al diseño de la aplicación.

8. Seguridad

Velum Via puede utilizar, según la función y el dispositivo:

  • cifrado del contenido antes de su transmisión;
  • conexiones cifradas durante el tránsito;
  • almacenamiento seguro de claves o secretos locales;
  • autenticación biométrica administrada por Android;
  • bloqueo u ocultamiento visual;
  • restricciones de captura de pantalla cuando Android lo permite;
  • tokens aleatorios de acceso;
  • controles de lectura, expiración y revocación;
  • políticas de acceso y validaciones en la infraestructura remota;
  • minimización de metadatos.

Ningún sistema puede garantizar seguridad absoluta. La protección también depende del dispositivo, el sistema operativo, la configuración de bloqueo, los permisos concedidos, la confidencialidad del enlace compartido y el uso responsable de la aplicación.

9. Conservación de los datos

9.1 Datos locales

Los datos locales pueden permanecer en el dispositivo hasta que:

  • el usuario los elimine desde la aplicación;
  • se cumpla una regla de expiración o limpieza;
  • la aplicación los purgue según la configuración disponible;
  • el usuario borre los datos de la aplicación;
  • el usuario desinstale la aplicación.

Algunos estados o registros locales pueden conservarse durante el período configurado para el Historial privado.

9.2 Datos remotos

Los registros remotos pueden conservarse mientras sean necesarios para permitir la lectura o aplicar las reglas elegidas por el creador.

Pueden dejar de estar disponibles o eliminarse cuando:

  • se alcanza el límite de lecturas;
  • se cumple la fecha de expiración;
  • el creador revoca el mensaje;
  • se ejecuta una acción de eliminación disponible;
  • una política técnica de limpieza elimina registros vencidos o inválidos;
  • el servicio debe eliminar información por razones de seguridad o cumplimiento.

Si un mensaje se configura sin expiración, puede permanecer disponible hasta que sea revocado, eliminado o alcanzado por una política técnica aplicable.

Copias residuales pueden permanecer temporalmente en respaldos o registros técnicos de los proveedores hasta completar sus ciclos ordinarios de rotación y eliminación.

10. Eliminación y control del usuario

El usuario puede controlar o eliminar información mediante las funciones disponibles:

  • eliminar mensajes locales;
  • mover o retirar mensajes del Historial privado;
  • revocar mensajes remotos enviados;
  • eliminar registros cuando la función correspondiente esté disponible;
  • borrar los datos de la aplicación desde Android;
  • desinstalar la aplicación;
  • cancelar o administrar una suscripción desde Google Play;
  • solicitar asistencia mediante privacy@usevelum.com.

Velum Via no exige una cuenta propia. Por este motivo, algunos registros remotos se identifican mediante tokens o enlaces aleatorios y no mediante el nombre o correo del usuario.

Si el usuario perdió el enlace, token o identificador necesario, Velum puede no estar en condiciones de localizar un registro anónimo concreto. Tampoco puede eliminar remotamente información que existe únicamente en el dispositivo del usuario.

La revocación impide o limita accesos futuros según el estado del mensaje, pero no puede borrar copias, fotografías, capturas o reproducciones que otra persona haya realizado previamente por medios externos.

11. Permisos del dispositivo

Velum Via puede solicitar:

  • Cámara: para detección local de presencia durante la lectura protegida.
  • Biometría o credencial del dispositivo: mediante el sistema de autenticación de Android.
  • Internet: para crear, consultar, abrir, revocar o eliminar mensajes remotos, verificar compras y acceder a páginas de soporte.
  • Notificaciones: únicamente si una función de avisos requiere este permiso en la versión instalada.

El usuario puede conceder, rechazar o revocar permisos desde Android. La denegación de un permiso puede impedir únicamente las funciones que dependen de él.

12. Enlaces, portapapeles y aplicaciones de terceros

Velum Via permite copiar o compartir enlaces mediante el portapapeles y el menú de compartir de Android.

Cuando el usuario comparte un enlace con una aplicación de mensajería, correo, navegador u otro servicio, esa aplicación puede procesarlo de acuerdo con sus propias políticas. Velum Via no controla el tratamiento realizado por el servicio elegido por el usuario.

Cualquier persona que obtenga un enlace válido y cumpla las condiciones de acceso podría intentar abrir el mensaje. El usuario debe proteger el enlace y, cuando corresponda, compartir la clave de lectura por un canal separado.

13. Lectura única, expiración, revocación y limitaciones

Las funciones de lectura única, expiración, límites de lectura, biometría, detección de presencia y revocación buscan reducir la exposición del contenido.

No garantizan que una persona no pueda:

  • fotografiar la pantalla con otro dispositivo;
  • memorizar o transcribir el contenido;
  • utilizar herramientas externas;
  • conservar información obtenida antes de una revocación;
  • acceder a una notificación o copia generada fuera del control de Velum Via.

La lectura única se refiere al acceso efectivo gestionado por la aplicación y no necesariamente a la apertura de una pantalla previa o a un intento fallido.

14. Menores de edad

Velum Via no está dirigida específicamente a niños.

Las personas menores de edad deben utilizar la aplicación únicamente con la autorización y supervisión de su madre, padre, tutor o responsable legal, de acuerdo con la normativa aplicable en su lugar de residencia.

Si se detecta que se recibió información personal de un menor de manera incompatible con esta política, podrá solicitarse su eliminación a privacy@usevelum.com.

15. Derechos y solicitudes

Según la legislación aplicable, el usuario puede tener derecho a solicitar:

  • información sobre el tratamiento de sus datos;
  • acceso;
  • rectificación o actualización;
  • eliminación;
  • oposición o limitación;
  • portabilidad, cuando corresponda;
  • retiro del consentimiento, cuando esa sea la base aplicable.

Las solicitudes pueden enviarse a privacy@usevelum.com.

Para proteger la privacidad, Velum puede solicitar información razonable para verificar la legitimidad de la solicitud. Sin embargo, debido al diseño sin cuenta y al uso de identificadores aleatorios, puede no ser posible asociar determinados registros con una persona concreta.

16. Cambios en esta política

Esta política puede actualizarse cuando cambien:

  • las funciones de Velum Via;
  • la arquitectura técnica;
  • los proveedores;
  • las prácticas de conservación;
  • los permisos;
  • las suscripciones;
  • los requisitos de Google Play;
  • la normativa aplicable.

La fecha indicada al comienzo identifica la versión vigente. Si los cambios son relevantes, podrán comunicarse en la aplicación, en el sitio web o mediante otros medios razonables.
